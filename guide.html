Technical guide

How Slipstream reads a release.

Graph traversal, critical-path math, PERT confidence, and FMEA scores run in deterministic TypeScript. A model is used only to write a short brief on Paid and Evaluation sites, and only after the scores exist.

Setup

The first page opens with no CSV, no spreadsheet, and no setup wizard.

  1. Install. A Jira admin installs Slipstream from the Atlassian Marketplace. Atlassian is the merchant of record. After the 30-day Evaluation, Paid is $4.00 per user per month, or $40 per user per year.
  2. Use a Fix Version. Put the release issues on a Fix Version and set its release date. That date is what the forecast is judged against. Issues without a version still appear on the portfolio view.
  3. Run the first scan. Open Slipstream from the Jira Apps menu or the project sidebar and choose Run scan. The page updates when the scan finishes.
  4. Read the gate. The header shows GO, CONDITIONAL, HOLD, or NO DATE, together with the chance of hitting the date and the length of the longest chain.

Release gates

The gate is evaluated after the scan. A missing number is never treated as a healthy release.

Screen Rule
HOLDWork still loops on itself, or the chance of hitting the date is below 50%.
NO DATEA Fix Version has no release date, or confidence cannot be calculated, and nothing stronger has already forced HOLD.
CONDITIONALConfidence is from 50% up to, but not including, 80%, or an open item is High or Critical risk.
GONumeric confidence is 80% or better, there is no cycle, no high-risk open item, and every watched Fix Version has a date.

High risk starts at a score of 150. Critical starts at 250. Each Fix Version card shows the target date, expected duration, the chance of hitting the date, and the projected finish. A missing date does not show a percentage.

What counts as a blocker

An item with no slack is on the longest chain. Slipstream also keeps weaker signals, and it labels how sure each one is.

  • A Blocks link — confidence 1.00.
  • A parent or child epic that crosses projects — confidence 0.90.
  • A branch, pull request, or commit name written in a comment or description — confidence 0.75.
  • A plain issue key written in the text — confidence 0.70.
  • The same Fix Version name in two different projects — confidence 0.60.

If work loops back on itself, Slipstream breaks the weakest link, marks the issues in the loop, and does not pretend the loop is a schedule. False keys such as UTF-8 or CVE-2026-1234 are rejected.

When an item has no story points, no time estimate, and no dates, Slipstream uses a plain default for that issue type and records the estimate source. A release made mostly of defaults is not called on track.

PERT and standard deviation

Slipstream does not ask a team to type optimistic, most likely, and pessimistic estimates. It takes the most likely duration already implied by the issue, then derives the three points.

  • Most likely, M, is the working-day duration from story points, the time estimate, or the issue-type default.
  • Optimistic O = 0.8 × M.
  • Pessimistic P = M × (1.5 + 0.25 × risk words). Risk words in the text include blocked, delay, risk, waiting, overdue, and slip.

Expected duration and variance for one item:

E = (O + 4M + P) / 6

variance = ((P − O) / 6)²

Along a path, variances add. The standard deviation is the square root of that sum. Confidence against a target date uses the standard normal distribution:

z = (T − E) / σ

The chance of finishing by T is the normal cumulative probability of z, using the Abramowitz–Stegun approximation. A target one standard deviation above the expected path is about 84%. The expected path itself is 50%. Two standard deviations early is about 2.3%. If the Fix Version has no release date, confidence and z are left empty. They are not shown as zero, and they are not shown as 100%.

FMEA formulas

Each open item gets one Risk Priority Number from severity, occurrence, and detection. Each factor is an integer from 1 to 10. Finished items score 0 and drop off the list.

RPN = S × O × D

The open range is 1 to 1,000. Bands are Low below 125, Medium from 125 up to 150, High from 150 to 249, and Critical at 250 or above.

Severity

Starts at 1. Add 4 when the item is on the critical path or its total float is zero. Add 3 when it blocks at least five other issues. Add 2 when those issues sit in two or more projects. Cap at 10.

Occurrence

Starts at 1. Add 2 for each sprint the item has already carried over. Add 1 for every four days since the last status change. Add 1 when the item’s PERT variance is at least 1 day squared. Cap at 10.

Detection

Starts at 2. Add 3 when the blast radius crosses projects. Add 2 when every incoming link is implicit. Add 2 when nobody owns the item. Add 1 when the duration is a default because the issue was unestimated. A cycle sets detection to 10. Cap at 10.

A critical-path, cross-project, unassigned item with two sprint carryovers, eight stale days, only an implicit incoming link, and five blocked issues across two projects scores S = 10, O = 7, D = 9, RPN = 630.

Inside the Jira issue

Open any issue and read the Slipstream panel. It shows whether the item is on the longest chain, what is blocking it, what it blocks, and the short brief. Names and email addresses are not shown. Copy Release Brief produces a note for the release review: the call, the chance of hitting the date, the longest chain, and the top risks. Account ids are left out.

What-if

Add delay, remove a dependency, or move the release date. Slipstream answers from the scan already on the page. It does not change Jira and it does not write a second plan to storage.
