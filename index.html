Know whether the release date still holds.

Slipstream reads the Jira work you already have, builds the dependency graph, and shows the critical path, the Fix Version odds, and the risks that can still move the date.

2-minute quick start

The first page opens with no CSV, no spreadsheet, and no setup wizard.

01

Install

A Jira admin installs Slipstream from the Atlassian Marketplace. Atlassian is the merchant of record. Paid is about $2.00 per Jira seat per month after the 30-day Evaluation.

02

Use a Fix Version

Put the release issues on a Fix Version and set its release date. That date is the PERT target. Issues without a version still appear on the portfolio radar.

03

Run the first scan

Open Slipstream from the Jira global or project page and choose Run scan. The page returns a job id. The graph, forecasts, and FMEA scores are read back from Forge SQL after the scan finishes.

04

Read the gate

The header shows GO, CONDITIONAL, or HOLD, plus PERT confidence and critical-path days. Engineers also see the same risk on the issue panel inside the ticket.

Reading the Release Radar

GO

No unresolved cycle, release confidence at 80% or above when a target date exists, and no open High or Critical RPN.

CONDITIONAL

Confidence from 50% up to 80%, or any open risk at RPN 150 or above. High is 150–249. Critical is 250 and above.

HOLD

An unresolved cycle remains, or release confidence is below 50%.

Fix Version forecasts

Each card is one stored Fix Version. The title is prefixed with the project key, so two versions that share a name stay distinct, for example BILL · Slipstream Sandbox Train. The card shows the target date, expected days ± standard deviation, the PERT confidence percentage, and the projected finish. A missing target date shows “No target date” instead of a percentage.

Critical path and dependencies

FLOAT 0 marks an issue on the critical path. Total float and free float are both shown. Explicit links and inferred links use separate badges:

  • Explicit Blocks link — 100% confidence
  • Cross-project epic parent or child — 90% confidence
  • Branch, pull request, or commit name written in a comment or description — 75% confidence
  • Plain issue-key mention — 70% confidence
  • Shared Fix Version — 60% confidence

A cycle is broken before the schedule is calculated. The removed edge is the lowest-confidence link, and the affected issues show a cycle alert. Detection for that anomaly is 10.

Unestimated default means story points, time tracking, and dates were all missing, so the duration used the issue-type default. The forecast warning counts how many items used that default.

FMEA risk scoring and the Jira issue panel

Every open issue receives RPN = Severity × Occurrence × Detection. Each factor is an integer from 1 to 10, so open RPN runs from 1 to 1,000. Done issues score 0 and stay off the top-risk board.

Severity, Occurrence, Detection

Severity reflects how much the issue can move the release. Occurrence rises with missing ownership, sprint carry-over, and schedule pressure. Detection rises when the estimate is weak, the link is implicit, or a cycle was broken. The radar shows S, O, and D next to the RPN.

Issue panel

Open any Jira issue and read the Slipstream panel. It shows the summary, numeric float with FLOAT 0 highlighted, upstream and implicit-upstream counts, downstream blast radius, the S / O / D breakdown, the owner role, and both the model brief and the deterministic brief when they are stored. Display names and email addresses are not shown.

What-If simulator and release brief

In-memory scenarios

Add delay days, remove a dependency, or shift a Fix Version target. Slipstream replays the schedule on the snapshot already loaded in the page. The simulation does not write Forge SQL and does not edit the Jira issues.

Copy Release Brief

Copy Release Brief builds a Markdown note with the stage-gate, readiness, confidence, critical path, cycles, and top risks. Account ids and email addresses are left out, so the note can be pasted into a release conversation.

Slipstream runs inside Jira Cloud on Atlassian Forge. Privacy, security, and support.
