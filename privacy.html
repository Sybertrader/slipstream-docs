Runs on Atlassian

Privacy policy and security

Slipstream is an Atlassian Forge app. It runs inside the customer’s Jira Cloud site. Compute, storage, and model calls stay on Atlassian infrastructure.

Privacy policy

The Marketplace vendor is Critical Path Works Ltd (Company No. 17585654, Registered in England and Wales). Atlassian hosts the app, Forge SQL, and @forge/llm. Atlassian is the merchant of record for Paid subscriptions.

Where processing happens

One hundred percent of Slipstream compute and SQL storage is Atlassian-hosted Forge. There is no vendor server, no external database, and no analytics or error-reporting service. permissions.external is empty. The app qualifies for Runs on Atlassian.

What is read

With the customer admin’s consent at install, Slipstream reads Jira work items, issue links, comments, descriptions, Fix Versions, sprints, and project metadata through Jira Cloud REST API v3 and the Jira Software fields discovered on the issue. It uses those fields to infer dependencies and to score schedule risk. It does not read Confluence in v1.0. It does not call /rest/dev-status. Branch, pull-request, and commit names are used only when someone has already written them into a Jira comment, description, or issue link.

What is stored

Forge SQL tables are keyed by the installation’s cloud_id, taken from Forge installContext. The app does not accept a tenant id from the browser. Stored work-item fields are issue keys, project keys, summaries, status category, estimate provenance, schedule math, dependency edges, FMEA scores, and release forecasts. The only person identifier stored is the assignee’s Atlassian accountId. Display names and email addresses are not written to Forge SQL. UI copy redacts any email address that appears inside a stored brief before it is shown.

Model use

@forge/llm runs only for an active Paid or 30-day Evaluation license, and only inside Forge. Each scan sends at most five highest-RPN chains. Excerpts are capped at 160 characters and treated as untrusted data. Free and expired installs make zero model calls. There is no third-party AI subprocessor. Prompts and completions are not sent to a vendor endpoint. Graph traversal, critical-path math, PERT confidence, and FMEA scoring run in deterministic TypeScript.

Retention and uninstall

Snapshot-scoped rows carry created_at. A daily job deletes rows older than 30 days in bounded batches of 1,000, at most 20 batches per run. A 35-day-old row is deleted. A 5-day-old row stays. Uninstall follows Forge’s installation data lifecycle: the app can no longer read that site’s Jira data, and Atlassian-managed deletion plus the same 30-day purge removes stored rows. There is no vendor copy to delete.

Sharing

Slipstream does not sell data, does not advertise, and does not deliver alerts through Slack, Teams, Discord, email, or webhooks. v1.0 shows the Stage-Gate brief in the Jira page and the issue panel. It does not declare write:jira-work and it does not post Jira comments.

GDPR and UK GDPR rights

Slipstream does not keep a separate user profile. A customer admin uninstalls the app from Jira administration to end processing for that site. An individual asks their Jira admin to clear or reassign the work item. The next scan overwrites accountId when the assignee changes, and the 30-day purge drops the stored identifier with the row. To access, correct, or object to processing of the stored accountId, contact the address below. The vendor acknowledges privacy and security requests within 24 business hours.

Security

  • Every SQL statement filters cloud_id from the installation context. A payload cloud id is ignored.
  • UI resolvers read precomputed Forge SQL. A manual scan checks the clicking user’s Jira browse permission before a job is queued. Issue reads for the scan run as the installed app only after that gate, or from a scheduled or product event.
  • Scopes are limited to reading Jira work, the assignee account id on the issue, software issue and sprint fields, and Forge app storage.
  • Forge SQL and Forge logs are Atlassian-operated. The app does not ship its own log drain.
  • Report a vulnerability to the security contact below. A fix ships as a Forge app version. Customers do not patch a server.

Security contact and support

Security inquiries go to support@criticalpathworks.com. Critical Path Works Ltd replies within 24 business hours and does not ask the customer to export a database.
