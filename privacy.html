Runs on Atlassian

Privacy and security

Slipstream is an Atlassian Forge app. It runs inside the customer’s Jira Cloud site. Compute, storage, and any model call stay on Atlassian infrastructure.

Security at a glance

Where it runs
Forge only. permissions.external is empty. There is no vendor server.
What it writes
Nothing in Jira. write:jira-work is not declared. v1.0 does not post comments or publish Confluence.
Person data stored
Slipstream stores the assignee’s account ID and display name only, never email addresses, and deletes them after 30 days.
How long rows stay
Rows older than 30 days are deleted daily. Runtime is Node.js 22.

Privacy policy

The Marketplace vendor is Critical Path Works Ltd (Company No. 17585654, registered in England and Wales). Atlassian hosts the app, Forge SQL, and the model. Atlassian is the merchant of record for Paid subscriptions.

Where processing happens

Slipstream compute and SQL storage are Atlassian-hosted Forge. There is no vendor server, no external database, and no analytics or error-reporting service. The app qualifies for Runs on Atlassian.

What is read

With the customer admin’s consent at install, Slipstream reads Jira work items, issue links, comments, descriptions, Fix Versions, sprints, and project metadata through Jira Cloud REST API v3 and the Jira Software Agile REST API. It uses those fields to infer dependencies and to score schedule risk. It does not read Confluence in v1.0. It does not call /rest/dev-status and it does not declare read:source-code:jira-software. Branch, pull-request, and commit names count only when someone has written them into a comment or a description.

What is stored

Forge SQL tables are keyed by the installation’s cloud_id, taken from Forge install context. The app does not accept a tenant id from the browser. Stored work-item fields are issue keys, project keys, summaries, status category, estimate provenance, schedule maths, dependency edges, FMEA scores, and release forecasts. Slipstream stores the assignee’s account ID and display name only, never email addresses, and deletes them after 30 days.

Model use

A model hosted by Atlassian through Forge LLM runs only for an active Paid licence or an active 30-day Evaluation, and only inside Forge. Each scan sends at most five highest-RPN chains. Each excerpt is capped at 160 characters and treated as untrusted data. The model never computes the graph, the path, the confidence, or the RPN. If the model is rate-limited or returns an error, the scan still finishes on the deterministic summary. A lapsed licence makes zero model calls.

Retention

Rows older than 30 days are deleted daily. There is no vendor copy of the site’s Jira data.

Sharing

Slipstream does not sell data and does not send Slack, Teams, Discord, email, or webhook alerts. v1.0 does not post Jira comments, does not publish Confluence pages, does not import CSV files, and does not connect to GitHub or any other product.

UK GDPR

Slipstream does not keep a separate user profile. A customer admin uninstalls the app from Jira administration to end processing for that site. An individual asks their Jira admin to clear or reassign the work item. The next scan overwrites the stored account ID and display name when the assignee changes, and the daily purge drops both with the row. To ask about what is stored, email support@criticalpathworks.com.

Security

Every SQL statement filters cloud_id from the installation context. A cloud id supplied by the page is ignored. UI pages read precomputed Forge SQL. Forge SQL and Forge logs are Atlassian-operated. The app does not ship its own log drain. A fix ships as a Forge app version.

Scopes

  • read:jira-work
  • read:jira-user
  • read:issue:jira-software
  • read:sprint:jira-software
  • read:board-scope:jira-software
  • storage:app

Those are the only scopes. There is no write:jira-work, no Confluence scope, and no read:source-code:jira-software.
