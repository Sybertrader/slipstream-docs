01

Catch the dependencies nobody linked.

Teams keep Blocks links when they remember. The date-moving dependency is often an issue key, or a branch, pull-request, or commit name, written into a Jira comment or description. Slipstream reads that text, marks the link as implicit, and shows how sure it is. A shared Fix Version across two projects is a release anchor, not a hand-drawn link.

No repository connection. Slipstream does not call Jira’s development-information API and does not read source code.

  • 1.00 Blocks link
  • 0.90 parent or epic, same project or another project
  • 0.75 issue key inside a branch, pull-request, or commit phrase in a comment or description
  • 0.70 plain issue-key mention
  • 0.60 shared Fix Version across two projects

02

A release gate with four answers.

The call is chosen in this order. HOLD if any cycle remains, or confidence is below 50%. NO DATE if confidence is empty, or an undated Fix Version would otherwise be GO. CONDITIONAL if confidence is from 50% up to but not including 80%, or any high-RPN item is still open. GO only when confidence is at least 80%, there is no cycle, no open high-RPN item, and no undated Fix Version.

Readiness starts at 100. It loses 40 for any unresolved cycle, 30 if confidence is below 50%, 15 if confidence is from 50% up to 80%, 15 for a missing date or confidence, and 10 per high-RPN issue, up to 30.

The brief is shown on the Slipstream page and in the issue panel. v1.0 does not post a Jira comment and does not publish a Confluence page. Read the gate rules.

03

See the FLOAT 0 chain.

The critical path is the longest chain of remaining work. Items with no slack are marked FLOAT 0. Each open issue gets a Risk Priority Number: Severity × Occurrence × Detection, each from 1 to 10. High starts at 150. Critical starts at 250.

A critical, cross-project, unassigned item with 2 sprint carry-overs, 8 stale days, implicit-only edges, and 5 downstream issues across 2 projects scores S10 × O7 × D9 = RPN 630, Critical.

What-If delays an item, or several items on Paid and Evaluation, or removes a dependency. It reruns the maths in memory. It never writes to Forge SQL or to Jira.

04

Where it appears in Jira

  • Global page and project page, titled Slipstream: radar, dependency map, Fix Version forecasts, and What-If.
  • Issue panel, titled Slipstream: the gate and a blocker warning inside the work item. On Paid and Evaluation, the panel also shows the stored brief when a model ran.

Install, open Slipstream, run a scan. No CSV, token, or setup form. A scan runs asynchronously and can take up to 900 seconds.

Pricing questions

Does the app count seats?

Free on the Atlassian Marketplace is for up to 10 users. Inside the app, Free is limited to 2 projects. An active Paid licence or Evaluation has no project cap and keeps the paid features at any seat count.

What happens when the Evaluation ends without a licence?

The site drops to Free: up to 10 Marketplace users, at most 2 projects inside the app, one scheduled and one manual scan per 24 hours, and a deterministic summary.

Who bills us?

Atlassian. Atlassian is the merchant of record for Paid subscriptions.

Do volume discounts apply?

Marketplace volume discounts, if they are set in the Partner Portal, apply on top of the $4.00 list price. The app does not apply them.

Does Free call a model?

No. Free and expired installs make zero model calls. The model never computes the graph, the path, the confidence, or the RPN.

Does it write to Jira?

No. It is read-only. v1.0 does not post Jira comments. What-If does not write to Forge SQL or to Jira.
